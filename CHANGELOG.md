## [0.1.3] - 2026-09-12

### Added

- **Debt repayment: five named debts paid (2026-09-12).** The five debts listed in the KP7-KP10 completion review, paid with architect-grade code. Each debt below names the debt, the fix, and the honest remainder.

- **Debt 1: FailureKind is typed, not derived from error-string prefixes.** `SandboxResult.error(String, FailureKind)` now requires the kind explicitly — a null kind throws (fail-loud: an unclassified failure must not silently default), and named factories `sandboxFailure(error)` / `blocked(blockedClass)` pin the semantic. All three in-repo producers (`ClassLoaderSandbox` catch, `ProcessSandbox` execute + runProcess catches, `CommandRunner` interrupt/IO catches) pin the kind at the throw site; `ProcessSandbox` javac/java non-zero exits stay `CODE_FAILURE` (the guest died, not the machine). The prefix-derivation path `deriveKind` is demoted to an external-compatibility fallback — in-repo callers never rely on it, and its javadoc says so. Tests: `SandboxFailureKindDebtTest` (7: wording-independent classification, null-kind fail-loud, typed blocked factory, compat factory, kind survives message rewording). agent-sandbox 73/73.

- **Debt 2: escalation budget is per-runId, with an instance-level fallback lane.** `SandboxSpec` gains `runId` (attribution key for run-scoped accounting; null means no attribution — callers without a run identity share the instance-level counter). `SandboxEscalator.tryAcquireBudget` routes by runId into a `ConcurrentHashMap<String, AtomicInteger>`; unattributed specs share one instance counter. A CAS loop (`acquireSlot`) counts only REAL upgrades — a rejected attempt does not move the ledger, so `getEscalationsUsed(runId)` is an honest monitoring number (the first draft's `incrementAndGet() <= budget` let denied attempts inflate the counter, caught by test and rewritten). Old `getEscalationsUsed()` survives as the instance-view compatibility hook; `getEscalationBudget()` is deleted after grep proved zero in-repo consumers. Tests: `SandboxEscalationBudgetByRunTest` (3: run A exhausts its budget, run B on the SAME escalator still escalates; unattributed specs fall back to the shared instance counter; three attribution lanes are independent). agent-sandbox 73/73.

- **Debt 3: injection defense sees through obfuscation (normalization layer), semantic slot pinned.** New `InjectionNormalizer` (agent-security): NFKC + zero-width strip (U+200B/C/D, U+2060, U+FEFF, U+FE00-FE0F) + explicit homoglyph folding of 44 confusable pairs (Cyrillic/Greek/Latin lookalikes, parallel `char[]` arrays with explicit \uXXXX escapes — the javadoc records why: a hand-typed lookalike string is exactly how the first draft shipped misaligned and mislabeled m as Cyrillic) + whitespace collapse; the javadoc is honest that this is a deny-list of the most common confusables, not a complete confusables database. New `InjectionJudge` port is the v2 semantic slot: three-state `Verdict` (INJECTION / CLEAN / UNKNOWN — a semantic judge is probabilistic, forcing a binary answer invents precision), a throwing judge fails open to the regex wall (fail-open contract in the interface javadoc), `absent()` null-object for zero-dependency defaults. New `LayeredResultSanitizer` implements the existing `ResultSanitizer` — the wall runs on the normalized view, the judge only reviews what the wall let through (cheap-first-expensive-second, the same discipline as `CascadeModelClient`), first-hit-wins. Existing consumers adopt it with zero changes (it IS a ResultSanitizer). Tests: `InjectionObfuscationDefenseTest` (10: Cyrillic і attack, zero-width "ig\u200Bnore", fullwidth ＳＹＳＴＥＭ, clean CJK passes unflagged, normalize idempotent + null-safe, paraphrase visible only to the judge, UNKNOWN abstains, wall hit short-circuits the judge at 0 calls, absent() null object, composition with SanitizerGuardrail via real API). agent-security 69/69.

- **Debt 4: red-team harness is a rerunnable rig, not an unrun story.** New `RedTeamHarness` (examples): the attacker is a `ModelClient` port (demo runs on a scripted `MockModelClient` — zero cost; production swaps in `OpenAiModelClient`/`AnthropicModelClient`), the defense is any `ResultSanitizer` (demo runs `LayeredResultSanitizer + InjectionJudge.absent()`), four seed categories (instruction-override / role-spoofing / sensitive-exfiltration / paraphrase), the attacker is told to paraphrase away canonical phrases so the wall is tested where it is weakest. Generation is fail-open (a dead attacker LLM lands in `generationsFailed`, reported honestly, never crashes the harness). Scoring: judge (whether the defense saw it) is separated from defense (the sanitizer) — a defense must not grade its own homework; `RunReport.penetrationRate()` and a human-readable report. Architecture note in the javadoc: this is a harness, not a test — it spends money to produce statistics, and the Moonlit golden set (M7) owns the pass/fail thresholds. Demo verified end-to-end: 4 generated, 1 flagged, penetration 75%, 3 generation failures honestly reported.

- **Debt 5: kill -9 crash recovery is real, across real OS processes.** New `KillNineCrashRecoveryTest` (agent-workflow): a real child JVM forked via `ProcessBuilder` runs charge → approval → payout with a `FileCheckpointStore`, pauses at approval, atomically writes `paused.marker` with the runId, then idles; the test JVM — a different OS process — `destroyForcibly()`s it (exit 137 = 128+9, SIGKILL convention asserted); a brand-new `RunManager` in the test JVM resumes from the dead process's checkpoint files and must SUCCEED. The replay detector is the shared `side-effects.log`: the child charged once before the kill, and the recovering process must not charge again (cursor protection across real process death). The approval decision survives the crash via a file-backed `FileApprovalService` (request/decision files, atomic move). Honest boundaries: the kill lands while the child is idle at the pause point (a kill DURING the checkpoint write — torn write — is a different failure mode, not covered); POSIX-only (`@EnabledOnOs({MAC, LINUX})`); exit code 137 asserted on POSIX only. agent-workflow 47/47 (46 existing + 1 new).

- **Context window budget, four accounts (KP2, Decision 24 P2).** The window is a budget, not a container. New `ContextWindowBudget` record (agent-core) splits the model's total window into four explicit accounts — `systemReserve` / `toolSchemaReserve` / `outputHeadroom` and the computed `historyBudget()` — with a compact constructor that rejects negative slots and reserves exceeding the total; `of(...)` for explicit sizing, `forWindow(n)` for the opinionated 10/15/20/55 split, and `window128k()` / `window32k()` / `window8k()` presets. "Who to cut when over budget" is an explicit product stance: v1 drops oldest history. `ContextWindowEnforcer` is a `ContextBuilder` decorator enforcing the budget at the model-request boundary: it drops oldest *logical units* — an ASSISTANT-with-tool-calls plus its trailing TOOL messages is one indivisible unit, because every provider rejects an orphaned tool result — and never drops the last message. Token estimation is the `chars / 4` heuristic throughout (no tokenizer dependency, consistent with agent-memory's `ContextBudget`). New `HandoffInputFilter` (Decision 24 P2) hangs on `HandoffSpec` and filters what the *next* model request carries after a handoff — `IDENTITY` (full carry, default), `keepWithin(budget)` (reuses the same pair-preserving trim), `lastTurn()` (from the last USER message) — while `AgentState.messages` is never rewritten: identity is configuration, history is fact, the state stays the audit ledger. Summary-carry is deliberately not a filter (needs a compressor writing a frozen summary — compose it as the target's `ContextBuilder`). New tests: `ContextWindowBudgetTest` (8), `ContextWindowEnforcerTest` (10), `HandoffInputFilterTest` (4). See [experiment notes](notes/experiment-kp2-context-window-budget.md) and [decision 24](notes/architecture-stance-decision-24-handoff-as-loop-config-swap.md).

- **Input and output guardrail doors (KP5).** The three-door theory is complete: tool-time governance already lived on `GovernedToolExecutor`; this adds the door before the model and the door before the user. New `Guardrail` interface (agent-core) with a mandatory `failMode()` — every rule explicitly declares `FAIL_CLOSED` (a throwing rule becomes a Block) or `FAIL_OPEN` (a throwing rule is skipped), no implicit default. `GuardrailChain` evaluates in order: first `Block` wins, `Rewrite`s compose (each later rule sees the previous replacement — chain order is priority). `GuardrailVerdict` is a sealed `Allow`/`Rewrite`/`Block`. INPUT door runs after `ContextBuilder.build` and before the model call: `Block` refuses the turn without calling the model (`AgentEvent.Error`), `Rewrite` rebuilds the request with the sanitized last-USER text while `AgentState` keeps the original — the ledger must show what the human actually said. OUTPUT door runs before the assistant message is persisted and before `AgentEvent.Done`: `Block` discards the model's answer entirely; `Rewrite` rewrites both the persisted message and the Done payload, so what the user sees, the ledger records, and the model sees next turn are the same text. New `SanitizerGuardrail` (agent-security) bridges the existing Stage 9 `ResultSanitizer` onto the doors (BLOCK strategy → `Block` verdict, SANITIZE/TRUNCATE → `Rewrite`), keeping the module boundary discipline (agent-core does not depend on agent-security). `AgentConfig` gains an 8-arg constructor + `getGuardrails()` (never null; empty = doors open; all existing constructors keep compiling). New tests: `GuardrailLoopTest` (5), `SanitizerGuardrailTest` (3). See [experiment notes](notes/experiment-kp5-guardrails.md).

- **A2A v2: streaming, push, and input-required resume (KP6).** The server's advertised card flips from `A2ACapabilities.none()` to `A2ACapabilities.v2()` — streaming and push are now real, stateTransitionHistory still honestly false. `message/stream` (SSE) emits the task lifecycle in order: `status(working)` → `artifact` (final text) → `status(terminal)`; the JSON-RPC id is not replayed on the stream — the events ARE the result. Client-side `streamTask` returns the ordered `A2AStreamEvent` list and records the local→remote id map so `getTaskStatus` keeps working after the stream. `tasks/pushNotification/set` binds a webhook URL to a task; the server POSTs the task JSON on input-required and terminal states (5s timeout, failure logs a WARN, the task is unaffected), and a task already past `working` that gets a webhook bound late is pushed once immediately — late subscribers don't miss the result. Resume: an agent may now pause a task by throwing `A2AInputRequiredException` — the server stores the task as `input-required` *with the `AgentState`*, and a follow-up `message/send` carrying `message.taskId` continues the same task and context (`continueTask` on the client); only `input-required` tasks can be continued — a completed/failed/rejected task is refused with `-32602` loudly (completed work must not be silently replayed), an unknown id still gets `-32001`. New tests in `HttpA2ARoundTripTest` (v1 9 + v2 3 = 13 total: `inputRequired_thenContinue_reusesState`, `streamTask_emitsWorkingThenCompleted`, `pushNotification_firesOnCompleted`). agent-mcp 79/79. Still in-memory, still 127.0.0.1, still no card signing, no webhook signing, no third-party interop verification. See [experiment notes](notes/experiment-kp6-a2a-protocol.md).

- **Sandbox spectrum: risk level → isolation tier (KP9, Decision 21 boundary made explicit).** Four new types in agent-sandbox: `SandboxRiskLevel` (TRUSTED / SEMI_TRUSTED / UNTRUSTED / ADVERSARIAL), `SandboxTier` (CLASS_LOADER / PROCESS / DOCKER / MICROVM / WASM — the last three documented placeholders, no implementation), `SandboxPolicy` (risk → tier mapping with the Decision 21 boundary: single-tenant + non-adversarial → ClassLoader; multi-tenant or user-pasted code → PROCESS; known adversarial → PROCESS + Docker in production), and `SandboxEscalator` with optimistic escalation for SEMI_TRUSTED: try ClassLoader first (fast, no JVM startup), and only when the code is *blocked* — not on timeout, since a timeout would time out again — escalate to Process for the second attempt. `ProcessSandbox` now actually applies `memoryLimitBytes` as the child JVM's `-Xmx` (exact MB uses `-XmxNm`, otherwise raw bytes; the javac compile step is deliberately not capped): test `memoryLimitBytesBecomesXmxOnChildJvm` asserts the child's `Runtime.maxMemory()` respects the limit. New tests: `SandboxPolicyTest` (11), `SandboxEscapeTest` (11, including `Runtime`/`File`/`ProcessBuilder`/`Class.forName` blocked by the ClassLoader sandbox and the theoretical escape paths documented as known-unguarded), `SandboxEscalatorTest` (9), ProcessSandboxTest +1. See [experiment notes](notes/experiment-kp9-sandbox-spectrum.md).

- **Resume-as-last-active-agent (handoff production hardening, Decision 24 P3).** `AgentState` gains `lastActiveAgentName`; after a handoff, re-entering through the entry agent continues as B — the host no longer needs to listen for `AgentEvent.Handoff` and swap entry points manually. Resolution goes through the new `HandoffTargetResolver`: the entry config's handoff graph is walked to find the named agent, and an unreachable name fails closed (`ERROR`, not a silent fallback to A). Target agents' tools use their own `AgentConfig.toolExecutor` (an explicitly mounted governance chain) instead of a silent `DefaultToolExecutor` — governance does not drop after a transfer. New tests: `HandoffLoopTest` +3 (`shouldResumeAsLastActiveAgentWhenReenteringEntry`, `shouldFailClosedWhenLastActiveNameIsUnreachable`, `shouldUseTargetOwnExecutorAfterHandoff`), `HandoffTargetResolverTest` (4: graph walk, fail-closed, executor preference), `AgentStateJsonTest` +1. agent-core 92/92.

- **Side-effect gap experiment (KP8, E8: what three protections each cover).** The crash window "side effect fired but result not yet on the blackboard" is now seven runnable assertions instead of one risk line in the modules map. New `E8SideEffectGapExperimentTest` (agent-workflow, 6 scenarios, zero production changes) simulates crashes by constructing a fresh `RunManager` over the same checkpoint directory with new workflow/approval instances, mirroring `EnterpriseTaskManagerTest.crashRecoveryFromCheckpointFiles`. Findings, each pinned by a test: (1) cursor protection — nodes before the pause node never replay; (2) without an `isResuming` guard a two-phase node charges twice across a resume (the bug, demonstrated); (3) the guard splits fire/poll so each runs exactly once; (4) a trace-derived idempotency key dedupes replays across crashes; (5a) the textbook key `runId:nodeId:attempt` mints a NEW key on retry — one logical visit delivered twice; (5b) the corrected formula `runId:nodeId:visitOrdinal` (ordinal = count of this node's SUCCESS records in the persisted trace) stays stable across crash and retry; (6) recovery granularity is the last pause, not the last node — `RunManager` only persists a checkpoint on PAUSED, so B/C-sequence nodes after the resumed node replay until the second pause, and the resumed approval node pauses again (its decision table is empty in the new process — document semantics, tests must re-setDecision). The Temporal/Orleans contrast lands in the notes: durable execution's real variable is persistence frequency, not the medium — Temporal persists every step (event sourcing, replay = recovery), Orleans snapshots + tail replay, agent4j persists only at pause points and covers the in-between gap with the three protections. Honest boundaries: simulated crash (fresh manager, not a real kill -9), single JVM, Temporal/Orleans compared from literature, not run. agent-workflow 46/46 (39 existing + 7 new). See [experiment notes](notes/experiment-kp8-durable-execution.md).

- **Failure kinds, honest sandbox report, escalation budget (KP9 completion).** Sandbox failures now bucket orthogonal to the tier. `SandboxResult` gains a 7th field `FailureKind` (SANDBOX_FAILURE / BLOCKED_BY_POLICY / TIMEOUT / CODE_FAILURE — the sandbox machine died / the policy refused / the time ran out / the code itself failed), derived in the compact constructor from `timedOut` and the error prefix with an explicit pin overriding the derivation; a 6-arg source-compatible constructor keeps every existing construction site compiling (`ProcessSandbox` untouched). `BLOCKED_BY_POLICY` is a design path, not an accident — it is the trigger for tier escalation. New `SandboxReport` is a pure downstream translator: `report(tier, result)` maps tier × outcome into guarantees / notGuaranteed / escalationNote, isomorphic to the KP7 HealthPipeline (enforcement acts, the report translates what was done into human-auditable promises) — blocked reports "the code never ran, the refusal itself is the guarantee", timeout on the ClassLoader tier admits "no hard-kill semantics (interruption is cooperative)", and the placeholder tiers (DOCKER/MICROVMM/WASM) loudly declare zero guarantees instead of impersonating implementations. `SandboxEscalator` gains an escalation budget (default 3 per escalator lifetime): a chatty-blocked source (adversarial prompts, or a model systematically fond of dangerous APIs) could weaponize optimistic escalation into denial-of-wallet — every request burning a 1-2s JVM startup; once the budget is spent the fast tier's BLOCKED result returns as-is and the strong tier never starts. `escalationBudget = 0` is the explicit disable switch; `getEscalationsUsed()` is the monitoring hook. Field types widen from `ClassLoaderSandbox`/`ProcessSandbox` to `Sandbox` (tests can inject scripted stubs); `isBlocked` prefers the structured `FailureKind` and falls back to the "Blocked:" prefix. Honest boundaries: kind derivation is coupled to the error-string prefixes (a tier rewriting its error text silently re-buckets — a structured error type is the follow-up debt); the budget is per-escalator-instance, not per-runId — multiple runs sharing one escalator dilute it, production should rebuild per run. New tests: `SandboxFailureKindTest` (7), `SandboxReportAndBudgetTest` (9: 6 translation assertions + budget exhaustion / zero-budget / observability). agent-sandbox 63/63 (54 existing + 9 new). See [experiment notes](notes/experiment-kp9-sandbox-spectrum.md).

- **Untrusted content enters the model request as data (KP10: SanitizingContextBuilder).** The missing L3 of the injection defense stack: retrieval/history/tool output reaches the model-request boundary with no second gate after the Stage 9 tool-output door. New `SanitizingContextBuilder` (agent-security, implements agent-core's `ContextBuilder`, the same decorator shape as `ContextWindowEnforcer` and `SanitizerGuardrail` — module boundary discipline intact, unplugged it just doesn't exist) wraps any delegate and does two deliberately separate things: sanitization (every TOOL-role message content passes the existing `ResultSanitizer` pattern library before the model ever sees it — one step earlier than the output door) and spotlighting (every non-SYSTEM message is wrapped in fixed `[UNTRUSTED CONTENT BEGIN/END]` delimiters, with a fixed `DATA_ONLY_NOTICE` prepended as a transient SYSTEM message — you cannot filter every attack string, but you CAN make the model structurally distrust free text). State discipline (decision 12): the builder returns a new list and never rewrites `state.getMessages()` — sanitized views for the model, raw bytes for the forensics ledger. Prefix stability (decision 26): delimiters and notice are fixed constants in fixed positions, so the wrapped prefix stays byte-identical across calls and the KV cache keeps hitting. The four-layer defense-in-depth is now complete: L1 spotlighting (new), L2 tool output as untrusted input (Stage 9 sanitizer, existing), L3 pre-request sanitization of everything the delegate returns (new — covers retrieved memories, not just tool output), L4 scoped identity (`IdentityConstrainedPermissionChecker`, existing). Honest boundaries: v1 is regex patterns, semantic detection (LLM judge) is the v2 interface slot; spotlighting is framing, not a guarantee — defenses stack, none is absolute; no real-LLM red-team run (Simon Willison-style cases belong to the Moonlit golden set). New tests: `SanitizingContextBuilderTest` (10: TOOL sanitization, clean passthrough, user-not-rewritten-only-framed, notice + wrapping, transient-SYSTEM not wrapped, spotlighting off, state keeps original bytes, byte-stable across calls, toolCalls survive rebuild, null/blank content passthrough). agent-security 59/59 (49 existing + 10 new). ## [0.1.2] - 2026-09-11

### Added

- **HTTP A2A, both directions (KP6).** agent4j is now a protocol citizen, not just a data-model tourist: `HttpA2AClient` speaks the A2A JSON-RPC dialect over real HTTP — `message/send` for task delegation, `tasks/get` for status polling, `GET /.well-known/agent.json` for discovery — and `HttpA2AServer` wraps an existing `Agent` as a protocol endpoint (JDK `HttpServer`, zero new dependencies; the agent itself is untouched, only how it answers the phone changes). The wire codec `A2AJson` is shared by both sides: where our model is richer than the spec (`taskType`/`sender`/`deadline`), the fields ride `params.metadata` so a spec peer that ignores metadata still round-trips what it understands; where the spec is richer than v1 (non-text parts), parsing skips instead of rejecting. Model alignment: `A2ATask` gains spec `contextId`/`status`/`artifacts` fields and `AgentCard` gains `url`/`capabilities`, with legacy 6-arg/5-arg constructors keeping all 170 existing construction sites compiling and behaving unchanged; task status is now the spec dialect (`working`/`completed`/`failed`/`input-required`/`canceled`/`rejected`, `A2ATaskStatus` enum) instead of free strings — `getTaskStatus` returns the enum, null for unknown tasks. Identity physics: the SERVER assigns task ids on the wire, so the HTTP client keeps a local-to-remote id map per instance. Defense on both sides of the wire: the server takes an optional inbound sanitizer (`UnaryOperator<String>`, a throwing sanitizer rejects the task as `rejected` BEFORE the agent runs — the a2a sibling of ExternalAgentWorker's outbound D5); the caller keeps wiring Stage 9's `ResultSanitizer` outbound as before. Honest v1 boundaries: synchronous execution only (no `message/stream` SSE, no push notifications), in-memory task store (lost on restart), no task continuation (a `message/send` carrying `message.taskId` is refused with `-32001`, loudly, not silently re-run), `sendMessage` refuses loudly over HTTP (the spec subset has no fire-and-forget method — faking it would silently CREATE a task), binds `127.0.0.1` only. New tests: `HttpA2ARoundTripTest` (real loopback sockets, zero mocks: full round-trip, discovery, failure, transport failure, restart-loses-store, inbound reject without running the agent, metadata rides the wire) and `HttpA2AServerProtocolTest` (raw-JSON protocol level: `-32601` unknown method, `-32700` parse error, `-32600` notification refusal, `-32001` continuation refusal / task-not-found, `-32602` non-text parts, HTTP verb rules, spec-dialect task shape). New example: `HttpA2AExample` (loopback demo: discover → send → poll → reject → supervisor routing over HTTP). agent-mcp 76/76 (59 existing + 17 new); agent-orchestrator 45/45 unchanged; full repo 22 modules BUILD SUCCESS.

### Added

- **PostgreSQL ledger (memory roadmap step 4).** The account book is now a database: `PgMemoryStore` is plain JDBC over a host-supplied `DataSource` (no pool, no ORM, no framework-owned migrations) with an idempotent schema of one 16-column ledger table, a `(scope, created_at DESC)` access index, and the step-4 centrepiece — a partial unique index `UNIQUE (scope, subject) WHERE status = 'ACTIVE'` that turns the reconciliation invariant "one ACTIVE line per subject" into a physical constraint: a racing second ACTIVE write surfaces as a unique violation instead of silently drifting into two. The `MemoryStore` port gains a default `supersede(closedOld, newEntry)` — sequential update-then-write in the default, overridden by `PgMemoryStore` as ONE transaction: a failure midway (e.g. the unique index rejecting the replacement after a racing writer won the slot) rolls the close back, so the ledger never ends with zero ACTIVE lines for a subject. All four supersede call sites (extract pipeline, `save_memory` tool, admin `approve`, admin `supersede`) now ride the atomic verb, and `EmbeddingMemoryStore` overrides it too so the decorator cannot silently decompose a persistent delegate's transaction. `write()` upserts on id (`INSERT ... ON CONFLICT (id) DO UPDATE`), the SQL shape of the in-memory map put — which lets approve activate a pending row in place inside the same transaction. Embeddings are stored as JSON float arrays in a text column, not pgvector: ranking happens in Java (`HybridRankingStrategy`), an ANN index buys nothing today, and a schema-pinned dimension would break embedding-model swaps; the upgrade path (`ALTER TABLE ... ADD COLUMN vector(dim)` + backfill + ANN index) never changes the ledger. Timestamps bind as `TIMESTAMPTZ` via `OffsetDateTime` UTC; enums bind as `name()` with strict `valueOf` read-back so a renamed enum value on old rows surfaces loudly. New abstract `MemoryStoreContractTest` turns the port's javadoc promises (scope isolation, ACTIVE-only default view, lazy TTL, exact filters, due windows, newest-first, upsert-on-id, the supersede move, full round-trips) into 19 machine assertions run against every implementation — `InMemoryMemoryStore` on every build, `PgMemoryStore` against a real zonky embedded PostgreSQL when `AGENT4J_PG_TEST=true`, including the two guarantees only a database can give: the partial index rejecting a second same-subject ACTIVE write (the first survives), and a mid-move unique violation rolling the close back (the racing writer's stamps survive, ours do not land). agent-memory 174/174 (134 existing + 40 new); PG line 21/21; full repo 22 modules serial BUILD SUCCESS. See [memory design discussion](notes/discussion-memory-system-design.md).

- **Layered memory injection (memory roadmap step 3, Letta core/archival alignment).** One recall, two tiers with different physics. The new `MemoryLayering` policy record (core importance threshold, default 0.9 + memory token budget, chars/4 heuristic) splits the recalled pool: core-tier entries (importance ≥ threshold) are the always-on working set, injected at the head as `[Core memories]` every turn, never ranked by the query and never dropped by the budget — stable head content keeps the prompt's longest-common-prefix long (E3 / decision 26 applied to memory). Archival-tier entries are paged in beside the last USER message as `[Known memories]`, re-ranked by relevance to that message — the same anchor the write-side reconciler uses, now defined once in `ConversationAnchors` so read and write can never drift — and trimmed by the remaining token budget. Placement physics: query-drifting content at the tail, identity content at the head. Recall is soft-failing: a broken recall degrades the turn's injection to "no memories", never breaks the chat loop. The 7-arg `MemoryContextBuilder` constructor opts in; the 6-arg constructor keeps the legacy single-block behaviour bit-for-bit, so all channel / tavern / enterprise call sites compile and behave unchanged. Flagship test: home-city (0.95) sits in core for every query while diet (0.7) and a keyboard purchase (0.65) trade places in archival depending on whether the user asks about lunch or keyboards. agent-memory 134/134 (129 existing + 5 new); full repo 22 modules serial BUILD SUCCESS, 2930 tests 0 failures. See [memory design discussion](notes/discussion-memory-system-design.md).

- **Reconciliation loop + bi-temporal timestamps (memory roadmap step 2).** The extract pipeline no longer extracts blind: `MemoryReconciler` recalls up to 20 ACTIVE old entries for the scope (read side feeds the write side) and renders them as an "Existing subjects" block in the extractor prompt, so the model picks an existing subject key instead of inventing a drifting one, and judges EVOLVE/CONFLICT against what the old entries actually say. `MemoryEntry` gains three bi-temporal fields — `validFrom` / `validAt` (business axis: when the fact was true in the world) and `invalidAt` (system axis: when the ledger closed the line) — with four backward-compatible constructors keeping all existing sites compiling unchanged. On supersede, the old entry is closed on both axes via `closedAs`: business axis at the NEW fact's business start (`validFrom`, falling back to `createdAt` — the user moved last week, not this Monday), system axis at now, so "when did I move" answers with the business date and old/new intervals never overlap. New `MemoryDecision` record captures every write decision (operation ADD/UPDATE/REJECT, subject, lifecycle, oldEntryId/newEntryId, recalled evidence, approvedBy, decidedAt/appliedAt) and is reported through the `MemoryDecisionListener` hook — the audit chain "who changed my memory and why". All three supersede sites (extract pipeline, `save_memory` tool, admin `approve`) follow one ledger rule. Soft failure throughout: a recall failure degrades to plain extraction, a broken listener never breaks the write. Flagship test: seed "home-city: lives in Shenzhen", feed "I moved to Shanghai" with `validFrom` = last week, assert Shenzhen becomes HISTORICAL with `validAt` = the business date (not recording time), Shanghai is the only ACTIVE entry, default recall sees Shanghai only, history query recovers Shenzhen, and one UPDATE decision is reported with both entry ids. See [memory design discussion](notes/discussion-memory-system-design.md).

- **Read-side semantic retrieval (memory roadmap step 1).** New `EmbeddingClient` port (`agent-core`) with `embed` / batch `embedAll` and a static `cosineSimilarity` that treats null/empty/mismatched vectors as "no signal" (0.0), plus `OpenAiEmbeddingClient` (`agent-model`) speaking the OpenAI-compatible `POST /embeddings` wire format (batch inputs, provider-side index re-ordering, same HTTP-status→ErrorCode mapping as `OpenAiModelClient`). `MemoryEntry` gains a 13th field `embedding` and an `embedText()` canonical text; three backward-compatible constructors keep all 56 existing construction sites compiling unchanged. New `EmbeddingMemoryStore` decorator (`agent-memory`) vectorizes entries on write with soft-failure semantics: an embedding outage logs a warn and writes the entry without a vector — read quality degrades, correctness never does; pre-vectorized re-writes pass through without re-billing. `HybridRankingStrategy` graduates from A8 stub to production (`score = 0.5·cosineSim + 0.3·tokenOverlap + 0.2·importance`) with a three-step degradation chain. Flagship test scenario: asking "relocation plans" surfaces `home-city: lives in Shenzhen` with zero lexical overlap. See [memory design discussion](notes/discussion-memory-system-design.md).

- **Prefix-cache visibility and a deterministic KV-cache simulator (E3, decision 26).** `CacheSimulatingModelClient` decorates any `ModelClient` and simulates prompt-cache prefix matching per model id: longest-common-prefix accounting against the previous prompt in the same domain, rough tokenization, hit/miss stats, and provider-reported `cachedTokens` wins when the vendor already reports hits. `CachePricing` prices a prompt in three mutually exclusive segments (`cached×read + written×write + base×input`, integer micro-USD) with `anthropic(...)` (read 0.1x, write 1.25x) and `openAiStyle(...)` (read 0.5x, writes free) factories. The `E3CacheExperimentTest` harness runs baseline / rewrite-flapping / rewrite-stable / tail-only / cascade scenarios under both pricing styles, each with a no-cache parallel line. Findings: compaction's volume reduction beats the cache loss it causes (even a flapping rewrite is cheaper than an untouched baseline); a frozen summary preserves ~24% more cache value than per-turn regeneration under Anthropic pricing; the ranking flips under OpenAI-style free-write pricing, so prefix discipline is vendor-priced, not a universal truth. See [experiment notes](notes/experiment-e3-prompt-caching.md), the [architecture walkthrough](notes/experiment-e3-architecture-walkthrough.md), and [decision 26](notes/architecture-stance-decision-26-cache-visibility-and-prefix-stability.md).

### Changed

- **`ModelResponse.TokenUsage` gains a fourth field, `cachedTokens`.** `promptTokens` stays the full billed prompt (Anthropic `cache_creation` folded in); `cachedTokens` is the cache-hit portion (Anthropic `cache_read`, OpenAI `prompt_tokens_details.cached_tokens`). The compact constructor clamps it (`< 0 → 0`, `> promptTokens → truncated`), and a 3-arg compatibility constructor defaults to 0 so existing construction sites compile unchanged. Wired through `CascadeModelClient`, `ModelCallMetrics` (7→8 params, compat constructor), `MetricsCollector` run totals, `RecordingSession` aggregation, and `TrajectoryCodec` JSON (`cached_tokens`; old archives read back as 0).
- **`ContextBuilder` javadoc gains a prefix-stability clause (SHOULD level, decision 26).** History rewrites should prefer a frozen summary over per-turn regeneration; flapping rewrites forfeit ~24% of the cache value a stable summary preserves (E3 simulation, Anthropic-style pricing). The clause is deliberately weak because cache hits are a runtime, post-hoc fact: a violation is not a compile error but a billing event, and `cachedTokens` visibility is the enforcement mechanism. See [decision 26](notes/architecture-stance-decision-26-cache-visibility-and-prefix-stability.md).
- **Breaking: persona is request-scoped, not conversation history.** ReAct injects `AgentConfig.systemPrompt` at each model request after context building; `AgentState` no longer receives it from `SimpleAgent.prepare`. Replace `AgentState(systemPrompt, userInput)` with `AgentState(userInput)` and `ChatSession.toAgentState(systemPrompt)` with `toAgentState()`, configuring the persona on `AgentConfig`.
- Old checkpoints containing a leading persona require explicit `AgentState.migrateLegacySystemPrompt(oldPrompt)` before execution; unmatched or additional SYSTEM history fails closed rather than being silently deleted. See [migration and decision 23](notes/architecture-stance-decision-23-system-prompt-at-request-boundary.md).
- Window/memory builders operate on history without a persona slot. ContextBuilder may return transient SYSTEM context but must not inject persona or persist SYSTEM into state. ChatEngine separates PersonaSource, HistorySource and transient sources; human handoff notes use USER history rather than SYSTEM privilege.

### Fixed

- **Streaming never terminated against Volcengine Ark.** Ark's final SSE chunk carries `content:""` and `finish_reason:"stop"` together; the parser returned early on the content branch, so `finish_reason` was never observed, `StreamEvent.Done` was never emitted, and `ReActAgentLoop` failed every turn with "Stream ended without a Done event". Every chunk is now inspected for every field, in a fixed order, with the terminal check last.
- Streamed tool-call `arguments` are merged by `index` across chunks. Previously every fragment but the last was discarded, so a tool call split across chunks arrived incomplete.
- Streams that end after `[DONE]` without `finish_reason` now emit a terminal event instead of being reported as an incomplete stream. A stream that produced nothing usable surfaces an `Error` rather than an empty answer that would be persisted as a blank reply.
- SSE `data:` lines without the conventional trailing space are now accepted.
